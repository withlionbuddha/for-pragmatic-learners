「눈치 없는 AI 신입과 2주 만에 검증하기: Rapid Hypothesis Validation」   
눈치 없는 AI 신입과 함께 2주 동안 가설을 수립하고, 실험을 설계·수행하여 기존 방식 대비 개선 효과와 적용 한계를 신속하게 검증합니다.   
* 눈치 없는 AI 신입과 일할 때는 빠른 산출물을 목표로 마음에 들지 않더라도 **그런가 보다** 여기며, 완성도는 2주 후에 계획 해야 합니다.  

기존 방식보다 나은 점이 있다면 무엇이며, 없다면 어떤 조건에서 한계가 나타나는가?

이 프로젝트는 양자 컴퓨팅의 원리를 코드로 이해하고, 고전적 방법과의 비교 실험을 통해 실제 활용 가능성과 한계를 확인하기 위한 공개 연구 저장소를 지향합니다.
프로젝트를 시작하는 이유
새로운 기술을 공부하거나 자격시험을 준비할 때, 실제 활용도와 투자 대비 효용은 중요한 판단 기준입니다. 기존 시스템보다 성능이나 비용 측면의 이점이 확인되지 않는다면, 해당 기술을 배우고 도입해야 할 필요성을 느끼기 어렵습니다.

이 프로젝트는 그 의문에서 출발합니다. 양자 기술로 시스템을 전환할 필요가 있는지 판단하려면, 같은 문제를 기존 방법과 양자 방법으로 풀고 결과를 비교할 근거가 필요합니다.

동시에 당장의 도입 실익과 연구의 가치는 구분해서 살펴봅니다. 원리를 이해하고, 적용 가능한 조건을 찾고, 효과가 없는 접근을 확인하는 것도 연구의 결과입니다. 향후 실용화 가능성은 검증할 대상으로 남겨 둡니다.  
  
목표
- 양자 회로와 최적화 과정을 실행 가능한 코드로 이해합니다.
- 동일한 문제에 대해 고전적 방법과 양자·하이브리드 방법을 비교합니다.
- 해의 품질, 실행시간, 메모리, 실행 비용을 기준으로 도입 실익을 평가합니다.
- 우수한 결과뿐 아니라 성능 저하, 실패, 재현되지 않은 결과도 기록합니다.
- 실험 코드와 설정을 공개하여 다른 사람이 결과를 검토하고 재현할 수 있도록 합니다.

핵심 질문
1. 동일한 문제에서 양자 방법은 기존 방법보다 어떤 이점을 제공하는가?
2. 비슷한 품질의 결과를 얻는 데 필요한 시간과 자원은 얼마인가?
3. 문제 규모와 실행 조건이 달라지면 결과는 어떻게 변하는가?
4. 관측된 차이는 양자 회로, 최적화 알고리즘, 구현 또는 실행환경 중 무엇에서 비롯되는가?
5. 확인된 이점이 시스템 전환과 운영 비용을 감수할 만큼 충분한가?

비교 실험 원칙  
아래 내용은 실험을 설계하고 결과를 공개할 때 적용할 기준입니다.  
항목	비교·기록 기준  
문제 정의	동일한 입력, 목적함수, 제약조건을 사용합니다.  
고전적 기준선	문제에 적합한 기존 알고리즘을 포함하고, 작은 문제에서는 가능한 경우 정확해와 대조합니다.  
실행 예산	동일 시간과 동일 평가 횟수를 별도 조건으로 비교합니다. 평가 1회의 비용도 기록합니다.  
해의 품질	목적함수 값, 제약 충족률, 알려진 최적값과의 차이를 기록합니다.  
실행시간	전처리, 회로 구성·변환, 최적화, 측정·후처리 시간을 구분하고 전체 소요시간을 함께 기록합니다.  
자원·비용	CPU·GPU·QPU 사용 조건, 메모리 측정 범위, 원격 실행 비용과 대기시간을 명시합니다.  
반복 실험	난수 시드와 반복 횟수를 공개하고 평균, 변동성, 실패 횟수를 함께 기록합니다.  
재현성	코드 버전, 의존성, 하드웨어, 실행 명령, 원시 결과를 함께 제공합니다.  


결과 해석 기준
- 시뮬레이터 실험과 실제 양자 하드웨어 실험을 명확히 구분합니다.
- 시뮬레이터에서 얻은 실행시간만으로 실제 양자 하드웨어의 속도 우위를 주장하지 않습니다.
- 목적함수 값의 개선과 실행시간·비용의 개선을 각각 평가합니다.
- 특정 문제와 설정에서 얻은 결과의 적용 범위를 명시합니다.
- 이점이 확인되지 않으면 해당 조건에서 도입 실익을 확인하지 못했다고 기록합니다.
- 실행하지 않은 실험과 검증되지 않은 가설을 측정 결과와 구분합니다.

공개할 실험 기록
각 실험에는 다음 내용을 포함하는 것을 원칙으로 합니다.
1. 해결하려는 문제와 비교 목적
2. 입력 데이터, 목적함수, 제약조건
3. 비교 알고리즘과 주요 설정
4. 실행환경과 재현 명령
5. 측정 결과와 원시 데이터
6. 결과 해석, 한계, 후속 검증 항목

Python project layout: `src/modules/` contains the importable package, `tests/` contains unit tests, `notebooks/` contains experiments, and `scripts/` contains the test runner.

From `quantum/` install with `python -m pip install -e .` and run `python -m pytest` (requires pytest). Alternatively run `bash scripts/exe_tests.sh`.

The notebooks prepend `quantum/src` to Python's module search path when started from the project root or its notebook directory.
